## 5. Failed Approaches -- DO NOT RETRY
- **AWS SSO default (PKCE auth-code) flow inside container** -- default `aws sso login` binds
  a callback server on `127.0.0.1:PORT` INSIDE the container; the host browser redirect to
  that port can't reach it → sign-in never completes. Also the script greps for a
  `https://device.sso...` URL (expects device-code flow) → mismatch. Fix: `--use-device-code`.
  Requires AWS CLI ≥2.22; image has 2.32.7. DO NOT drop the flag.
- **docker-compose bind mount with `bind.propagation: rslave`/`rshared` on macOS Docker Desktop**
  -- daemon rejects it: `path /host_mnt/Volumes ... is not a shared or slave mount`, container
  won't start. macOS host mount isn't marked shared. Fix: plain bind mount (no propagation).
  Consequence: drives plugged in AFTER container start need `docker compose restart`. Native
  Linux hosts CAN add `propagation: rslave` for live propagation.
- **(carried forward) GitHub headless auto-auth blocked by org SAML SSO + MFA** -- SleepNumberInc
  enforces Microsoft SAML+MFA on the GitHub OAuth grant; cannot clear headlessly. This session
  it also blocked `git push`: active gh account `rob-vance_snlabs` got "Repository not found";
  had to `gh auth switch --user sn-ravance` (the account with org access) before push worked.
  Use PAT / the sn-ravance account for org ops. See memory `github-auth-saml-sso-wall`.
- **(carried forward) Docker image build behind Zscaler fails with curl exit 60** -- SSL cert
  verify failure on github.com download. certs/ was empty. Fix: export host Zscaler Root CA
  (`security find-certificate -a -c Zscaler -p /Library/Keychains/System.keychain > certs/zscaler.crt`)
  before `docker compose build`.

- **Seeder detecting login by navigating to /settings/profile every 2s** -- yanked the tab away

- **Cookie check requiring `logged_in=yes` + `user_session`** -- too strict, missed real login.

- **`page.goto(github, {waitUntil:'networkidle'})`** -- never settles on GitHub (long-poll),
  30s timeout. Use `domcontentloaded`.
- **Headless GitHub device-flow auto-authorize with a seeded GitHub session** -- assumed the
  GitHub cookie seed was enough. FALSE: after clicking Authorize, org policy redirects to
  `login.microsoftonline.com/.../saml2` (MFA). Cannot clear MFA headlessly, and it's a headless
  container (no window for the user). This is why the user must use a PAT. Playwright drives
  GitHub's own screens fine; the wall is Microsoft SSO+MFA. See memory
  `github-auth-saml-sso-wall`.
- **Treating an Authorize-button CLICK as success** -- gave a false "authorized" while gh never
  got a token (SAML intercepted). Only success TEXT (congratulations/connected) counts.
